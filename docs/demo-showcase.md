# Synthetic showcase materials (`pnpm demo:capture`)

`pnpm demo:capture` drives the running local demo in a headless browser and saves a
shareable set of product materials:

- three new four-page books (English, Russian, Polish) created through the real wizard,
  generated by the real generation worker, and read in the completed reader;
- each book's PDF, downloaded through the reader's **Download PDF** button;
- screenshots of the wizard, the reader, and the published interactive story;
- a `manifest.json` that identifies and hashes every file.

Everything is produced by the **mock** story, character, and image providers. The materials
show the product and the pipeline working end to end. They say nothing about the quality of
real-model generation, and must not be presented as if they did.

## 1. Start the local demo

The capture command does not start anything. Start the disposable demo first, in its own
terminal, and wait for the ready banner (see [local-demo.md](local-demo.md#one-command-demo-pnpm-demolocal)):

```bash
pnpm demo:local
```

The capture uses only that demo's loopback addresses (`http://127.0.0.1:3100` and
`http://127.0.0.1:4100/api`) and its synthetic verified account
(`verified-login@e2e.storyme.test`).

## 2. Capture

In a second terminal:

```bash
pnpm demo:capture
```

It takes about two minutes. The command:

1. exits with status `2`, creating nothing, if the API or web app is not answering;
2. creates a new run directory `artifacts/demo-showcase/<UTC timestamp>-<random>/`. It never
   reuses an existing directory;
3. signs in, then for each language: completes the wizard on a 320px viewport (checking that
   every wizard stage fits at 320px and 390px), opens **View provider-work estimate** and
   reads the server's answer, clicks **Generate Story**, waits for the completed reader,
   pages to page 1, and downloads the PDF;
4. starts **The Last Delivery** from the interactive catalogue, makes one choice, reloads the
   page and checks that the same session resumed, then plays the existing route to the
   _Ledger Exposed_ ending.

**Provider guard.** Before each **Generate Story** click, the capture reads the
server-owned generation estimate (`GET /api/books/:id/generation-estimate?kind=initial`).
It continues only when `providerMode` is `"mock"`. Any other or missing value stops the run
before generation is dispatched, with status `3`. Cost fields are never used to decide this.

It never migrates, reseeds, restarts, or stops a service, and it creates no new interactive
scenario. Screenshots show the app as rendered. The capture waits for real page content and
for every captured illustration to finish decoding. It stops if a captured view shows an
error alert, if the Next.js dev badge reports an error, or if **Generate Story** is refused.

**Repeat runs.** Each run generates three books, and the API allows 10 generations per account
per hour (`GENERATION_RATE_LIMIT_*`). So one demo session supports three captures an hour;
a fourth stops with `Generate Story was refused with HTTP 429`. Restart `pnpm demo:local` for
a clean session (it also resets the library) rather than raising the limit. Each run also
adds one interactive session to the account.

## 3. Output

```
artifacts/demo-showcase/<run>/
  manifest.json
  pdf/storyme-en.pdf
  pdf/storyme-ru.pdf
  pdf/storyme-pl.pdf
  screenshots/wizard-320-step-1-child.png      (also step-2-story, step-3-review)
  screenshots/wizard-390-step-1-child.png      (also step-2-story, step-3-review)
  screenshots/reader-desktop-en.png            completed reader + PDF actions, 1280×900
  screenshots/reader-mobile-en.png             completed reader + PDF actions, 390×844
  screenshots/reader-page-1-en.png             interior page, one per language
  screenshots/reader-page-1-ru.png
  screenshots/reader-page-1-pl.png
  screenshots/interactive-play-desktop.png     mid-story, before the reload check
  screenshots/interactive-ending-desktop.png   the ending
```

`artifacts/` is ignored by Git. Stopping `pnpm demo:local` deletes the demo's database, the
synthetic account, and its files under `apps/api/tmp`, but **not** this directory: the
captured materials stay until you delete them.

`manifest.json` records:

| Field           | Contents                                                                              |
| --------------- | ------------------------------------------------------------------------------------- |
| `status`        | `complete`, or `incomplete` plus `failure.step` and `failure.message`                 |
| `git`           | `head` commit and `trackedChanges` (whether tracked files differed from `HEAD`)       |
| `providers`     | `designation: "mock"` and how it was established                                      |
| `inputs`        | the synthetic wizard inputs (names, ages, themes, lessons, page count); no photos     |
| `books[]`       | `bookId`, `title`, `publishedEdition`, estimate `providerMode`, PDF path, screenshots |
| `interactive`   | `sessionId`, `scenarioId`, `scenarioVersion`, route choices, ending, screenshots      |
| `viewports`     | the desktop (1280×900), mobile (390×844), and narrow (320×740) sizes used             |
| `artifacts[]`   | every other file: run-relative `path`, `bytes`, `sha256`                              |
| `validations[]` | each check's `name`, `passed`, and `detail`                                           |

The directory never contains tokens, cookies, environment values, browser traces, or
diagnostics payloads. The access token is held in memory only, for read-only checks.

**Incomplete runs.** If any step or check fails, or you press Ctrl+C, the command writes
`manifest.json` with `"status": "incomplete"` and the failed step, keeps whatever was
already captured, and exits non-zero (`1` for a failure, `3` for the provider guard, `130`
for Ctrl+C). Do not share an incomplete run as a showcase.

## 4. Check the artifacts

The capture validates each run itself and stops on the first failed check:

- each book is `complete`, has 4 pages and a published edition, and its title/page text is in
  the requested script (Latin, Cyrillic, or Polish diacritics) with no `U+FFFD`;
- each downloaded PDF starts with `%PDF-`, ends with `%%EOF`, has 6 pages (cover, 4 story
  pages, back cover), embeds a TrueType font and at least one image, and is byte-identical
  to `GET /api/books/:id/pdf/preview`;
- the wizard has no horizontal overflow at 320px or 390px at any stage;
- reloading the interactive story resumes the same session without creating another.

Before sharing a run:

1. Confirm `"status": "complete"` and that every `validations[].passed` is `true`.
2. Recompute the hashes and compare them with `artifacts[]`:

   ```bash
   cd artifacts/demo-showcase/<run>
   sha256sum pdf/*.pdf screenshots/*.png         # macOS: shasum -a 256 …
   ```

   PowerShell: `Get-FileHash pdf\*.pdf, screenshots\*.png -Algorithm SHA256`.

3. Open each PDF and look at it. The PDFs subset and encode their font, so searching raw
   bytes for text proves nothing (see [PDF_UNICODE_VERIFICATION.md](PDF_UNICODE_VERIFICATION.md)).
   If `pdftotext` (Poppler or Xpdf) is installed, `pdftotext -enc UTF-8 pdf/storyme-ru.pdf -`
   should print readable Cyrillic, and the Polish file readable `ą ć ę ł ń ó ś ź ż`.
4. Look at every screenshot: real text and illustrations, no error banners, no clipped
   wizard steps.

## 5. Limitations

- Mock providers produce deterministic template text and generated placeholder
  illustrations. They do not show real-model writing or artwork.
  Mock titles use the theme's first word (`Ada's lighthouse Adventure`), which is why the
  synthetic themes are short.
- The PDF checks are structural. Glyph correctness is covered by the renderer-level Unicode
  test and by looking at the files; the capture does not extract or render PDF text.
- The demo web app runs `next dev`, so its round **N** dev badge appears in the bottom-left
  corner of every screenshot. It is left visible on purpose: hiding it would also hide the
  error state it reports.
- The reader screenshots frame the **Read your book** section. Above it, the completed-book
  page shows the **Generated story preview**, which includes each page's raw illustration
  prompt. That is current product behaviour, not something the capture adds.
- Download file names are ASCII slugs of the title, so `Łódka` becomes `dka` and the Russian
  book downloads as `storyme-book.pdf`. The capture saves each file as `pdf/storyme-<lang>.pdf`
  and records the browser's suggested name in `books[].suggestedFilename`.
- At 320px the review step's long values (theme, lesson) wrap against their labels. The step
  indicator fits; the review rows are unchanged.
- Only Chromium is used. The mobile screenshots use a 390px viewport, not device emulation.
- The interactive story is the already published **The Last Delivery**, played along the
  route the interactive E2E suite uses.
- The capture shares the demo's synthetic account. Several runs against one demo session
  accumulate books in its library; that is visible in the dashboard, not in the screenshots.

## 6. Recording walkthrough (3–5 minutes)

Record from a fresh `pnpm demo:local` at a 1280×800 browser window on
`http://127.0.0.1:3100`, signed in as the synthetic account. Say once, at the start, that the
demo uses mock providers.

1. **Library (0:00–0:20).** Show **Family library** with its fixture books. Point at the
   header navigation: Family library, Child profiles, Interactive story.
2. **Wizard (0:20–1:10).** Click **+ New Book**. Narrow the window to phone width to show the
   three steps fit, then widen it again. Enter `Мила`, age 6, then Russian, theme
   `Ёжик и зимний лес`, 4 pages, and the lesson `Делиться с друзьями — это радость`. Show
   the review step and click **Create Book**.
3. **Generation (1:10–1:50).** Click **View provider-work estimate** and point out that it
   is an estimate (no external cost in mock mode). Click **Generate Story** and let the
   status move through its stages to **Your PDF is ready**.
4. **Reader (1:50–2:40).** Scroll past the story preview to **Read your book** and page
   through the cover, a story page or two, and the back cover. Show **Edit page text** without
   saving.
5. **PDF (2:40–3:10).** Click **Open PDF** and scroll through the Cyrillic pages. Close it and
   click **Download PDF**.
6. **Interactive story (3:10–4:30).** Open **Interactive story**, then **Start story** on
   _The Last Delivery_. Choose _Ask the caretaker where Tomasz is_. **Reload the page**: the
   same scene and the entry card in **Carrying** come back. Continue: _Climb to the fourth
   floor_, _Use the single-use entry card on the lock_, _Take the service stairs down to the
   cellar_, _Carry the original ledger up and confront Ines_ — the _Ledger Exposed_ ending.
7. **Close (4:30–4:50).** Return to the library to show the new book next to the fixtures.

Stop the demo with Ctrl+C afterwards. The recording is the only thing that persists.
